# Photo Scanner & Bot

> Розподілена мікросервісна система для візуального пошуку та каталогізації зображень за допомогою комп'ютерного зору (DINOv2) та векторної бази даних Qdrant.

> Проєкт надає повноцінний пайплайн: веб-інтерфейс для пакетного завантаження та адміністрування бази референсів, Telegram-бот для миттєвого пошуку схожих зображень за фотографією користувача та ізольований ML-сервіс інференсу.

## ✨ Ключові можливості
- **Семантичний пошук за вмістом:** пошук візуальних збігів за вектором ознак без необхідності точного текстового збігу тегів.
- **Два клієнтські інтерфейси:**
  - **Telegram-бот (Aiogram 3):** мобільний клієнт — надсилаєте невідоме фото в чат і отримуєте найбільш схожий предмет з бази, оцінку схожості та збережений опис.
  - **Веб-панель (NiceGUI):** інструмент керування базою — пакетне (батч) завантаження фотографій, попередній перегляд, додавання описів, пагінована галерея та масове видалення.
- **Ефективний інференс на CPU:** оптимізована збірка PyTorch для роботи на звичайних процесорах із динамічною розбивкою пакетів зображень на під-батчі.
- **Ізольоване зберігання медіа:** файли зберігаються на диску під неконфліктними UUIDv7-ідентифікаторами, а векторна база оперує виключно відносними шляхами та метаданими.
- **Zero-Setup Deployment:** запуск усієї розподіленої інфраструктури однією командою через Docker Compose без налаштування локального Python чи віртуальних середовищ.

## 🏗️ Архітектура та принципи взаємодії

Система побудована за мікросервісним принципом із чітким розділенням зон відповідальності:

### 1. Компоненти системи
* **Telegram Bot (`bot/`)** — *Aiogram 3.29, httpx*
  Клієнт пошуку. Приймає фото від користувача в пам'ять (in-memory buffer), запитує обчислення вектора у ML-сервісу та виконує пошук найближчих сусідів у Qdrant.
* **Веб-панель (`web/`)** — *NiceGUI 3.15, Pillow*
  Адміністративний UI. Пакетне завантаження фотографій з описом, статична роздача медіафайлів, пагінація галереї та каскадне видалення записів (з БД і сховища).
* **Сервіс ембедингів (`embedding_service/`)** — *FastAPI, PyTorch (CPU), Transformers, DINOv2*
  ML-інференс. Модель завантажується в пам'ять один раз при старті (`lifespan`). Приймає пачки зображень через multipart HTTP, виконує динамічний батчинг на CPU та повертає 2D-матрицю векторів розмірністю 768.
* **Векторна база даних (`qdrant`)** — *Qdrant, qdrant-client (AsyncClient)*
  Зберігання та індексація ембедингів. Зберігає вектори разом із метаданими (ім'я файлу на диску, опис, категорія, timestamp).
* **Спільне ядро (`core/`)**
  * `storage.py` — локальне сховище: запис байтів під UUIDv7, видалення файлів, робота виключно з відносними шляхами.
  * `database.py` — обгортка над Qdrant: створення індексів, пакетний `upsert`, пошук `query_points`, скрол та масове видалення.
  * `api_client.py` — асинхронний HTTP-транспорт (`httpx.AsyncClient`) з обмеженням черги через `asyncio.Semaphore`.
* **Інфраструктура:** *Docker & Docker Compose*
  Спільна віртуальна мережа, персистентне сховище для медіафайлів (`data/reference`) та окремий іменований том для кешу ваг моделі (`hf_cache`).

### 2. Потоки даних (Data Flow)

#### Сценарій індексації (Адмін-панель):
1. Користувач додає пачку фотографій у веб-панелі та заповнює текстові описи.
2. Веб-сервіс передає байти файлів до `embedding_service` через єдиний пакетний запит.
3. Сервіс обчислює вектори DINOv2 для всієї пачки й повертає масив ембедингів.
4. Модуль збереження записує фотографії на диск під іменами стандарту UUIDv7.
5. Клієнт бази створює записи в Qdrant, записуючи вектор і метадані (шлях до файлу, опис, категорія) одним атомарним викликом `upsert`.

#### Сценарій пошуку (Telegram):
1. Користувач надсилає фотокадр у чат бота.
2. Бот завантажує байти в оперативну пам'ять і робить запит до `embedding_service`.
3. Отримавши числовий вектор, бот виконує запит пошуку найближчих сусідів (`query_points`) у Qdrant.
4. База повертає найбільш схожу точку та збережений опис.
5. Бот бере знайдене референсне фото зі спільного сховища і надсилає його користувачеві разом із відсотком схожості та описом.

## Швидкий запуск

### 1. Клонування репозиторію

``` bash 
git clone https://github.com/dmitrovskii/photo-scanner-bot.git
cd photo-scanner-bot
```

### 2. Налаштування змінних середовища
Створіть робочі файли .env на основі шаблонів:

``` bash
# Конфігурація клієнтських сервісів (бот, веб-панель)
cp .env.example .env

# Конфігурація мікросервісу векторів
cp embedding_service/.env.example embedding_service/.env
```

Відкрийте кореневий .env та вкажіть ваш Telegram Bot Token, отриманий від @BotFather:
```bash
BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrSTUvwxYZ
```

### 3. Запуск контейнерів
```bash 
docker compose up --build
```

> **Примітка:** під час першого старту сервіс завантажить ваги моделі комп'ютерного зору DINOv2. Завдяки змонтованому тому `hf_cache` наступні перезапуски відбуватимуться миттєво.

## 🛠️ Зупинка та керування

* **Перегляд логів:**
  ```bash
  docker compose logs -f
  # або лог окремого компонента:
  docker compose logs -f embedding-service
  ```

* **Зупинка сервісів:**
  ```bash
  docker compose down
  ```

* **Повне очищення разом із базою даних та кешем моделі:**
  ```bash
  docker compose down -v
  ```
